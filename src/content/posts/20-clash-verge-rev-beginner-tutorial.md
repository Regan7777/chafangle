Clash Verge Rev 是运行在电脑上的网络客户端。它负责读取配置、选择节点、让 Windows 的浏览器或应用按指定规则连接；它本身不提供账号、订阅或节点。对第一次接触的人，先记住三个对象：**订阅链接**是服务商后台给出的配置地址，**节点**是订阅里的可选连接项，**规则模式**决定哪些流量走节点、哪些保持直连。不要把客户端当作订阅服务，也不要在还没确认基础网络可用时同时改 DNS、TUN 和规则。

## 一、开始前：确认系统、来源与准备项

准备一台能正常联网的 Windows 10 或 Windows 11 电脑、一个已从合规服务商后台获取的订阅链接，以及一个普通浏览器。先关闭其他正在接管代理的工具，例如旧版客户端、企业 VPN 或浏览器代理扩展；同一时刻只保留一个代理管理者，后续排错才有明确结果。

Clash Verge Rev 的安装包应只从 [Clash Verge Rev 官方 Releases 页面（外链）↗](https://github.com/clash-verge-rev/clash-verge-rev/releases) 下载。大多数 Intel/AMD 电脑选择 Windows x64 安装包；若设备是 Windows on ARM，才选择 ARM64 构建。不要从“绿色版整合包”、网盘转存或不明下载站取得安装包，也不要为了安装而关闭 Windows Defender、防火墙或 SmartScreen。若系统弹出安全提示，先回到官方发布页核对版本、文件名和发布来源；无法确认来源就停止安装。

**检查点：** 下载页面的仓库名称为 `clash-verge-rev/clash-verge-rev`，安装完成后能在开始菜单找到 Clash Verge Rev。此时还没有导入订阅，不能据此判断节点或网络是否可用。

## 二、安装并完成首次启动

1. 双击官方安装包，按 Windows 安装向导完成安装。
2. 从开始菜单启动 Clash Verge Rev。首次启动后，通常会在任务栏通知区域显示图标；点开主窗口，先停留在“设置”或“主页”确认程序没有立即退出。
3. 不要急着开启系统代理或 TUN。先检查程序界面能正常显示“订阅”“代理”“设置”等入口；若界面文字或模块加载不完整，先完全退出程序后重新启动。
4. 若版本提示更新，可先记录当前版本号。只有确定更新来自官方 Releases 时才更新；旧配置不必在首次启动时反复导入。

**正常结果：** 客户端窗口可打开、没有“内核无法启动”或持续重启的提示，且 Windows 本身的普通网页在不开代理时仍可访问。

**如果启动即报错：** 不要下载第三方内核替换文件。先确认安装包是否与系统架构一致；完全退出旧版或其他代理客户端后重启一次应用。仍无法启动时，保留错误提示和版本号，回到官方发布页查看该版本说明或提交问题，而不是盲目改系统权限。

## 三、导入订阅：先确认“导入成功”，再谈连接

1. 登录你已使用的合规服务商后台，找到“订阅”“Clash/Mihomo 订阅”或类似入口，复制完整链接。链接通常很长；复制时不要漏掉开头，也不要夹带空格、引号或换行。
2. 在 Clash Verge Rev 左侧打开“订阅”，新增链接订阅，粘贴后保存。
3. 对刚添加的订阅执行“更新/刷新”。更新结束后再进入“代理”页面，而不是立刻打开系统代理。
4. 在“代理”页面确认出现策略组或节点列表，选择一个名称清晰的节点。第一次测试只选一个节点即可，不要一次批量改动十几个选项。

**正常结果：** 订阅旁出现最近更新时间，代理页有节点或策略组，数量与服务商后台大致相符。此时只说明配置已被客户端下载，不代表每个节点都能使用。

**订阅更新成功但节点没有变化：** 先看更新时间是否真的改变；如果没有，可能只是点击未执行或链接失效。再检查后台是否刚修改过套餐或节点；不要重复新增同一条订阅。需要确认订阅格式、失效链接与安全转换边界时，下一步看 [订阅格式与安全转换指南](/posts/37-subscription-format-conversion-guide)。

**看到 HTTP 401、403、404 或 429：** 401/403 往往表示链接需要授权、已失效或访问被限制；404 常见于后台路径已更换；429 表示请求过于频繁。先回服务商后台重新复制链接，等待一段时间后只刷新一次；不要把订阅交给陌生在线转换站。

## 四、先用“系统代理”完成第一轮验证

系统代理是 Windows 上最适合第一步验证的方式。它主要影响遵循 Windows 代理设置的浏览器和应用；这一步成功后，再决定是否有必要启用 TUN。

1. 在“代理”页选择一个节点；优先选择延迟测试正常、名称清楚的节点。
2. 打开“设置”，找到“系统代理”，开启它。不同版本的菜单文字略有差别，但应能看到已启用状态。
3. 保持规则模式，不要先用全局模式。打开浏览器访问一个平常可打开的网站，再访问你需要验证的目标网站。
4. 回到客户端查看连接/日志是否出现新记录。测试结束后，知道开关在哪里再继续下面的步骤。

**正常结果：** 系统代理显示开启；浏览器至少能正常加载网页；客户端连接或日志页有新的请求记录。若普通网页和目标网站均无法加载，先关掉系统代理，确认电脑直接联网正常，再换一个节点重新测试。

**系统代理显示已开，但浏览器没有变化：** 先关闭浏览器内安装的代理扩展，再检查 Windows 设置中的代理状态是否由本客户端接管。企业 VPN、旧版代理工具和安全软件也可能覆盖系统代理；一次只运行一个。仍不一致时，先用不同浏览器交叉验证，不要立即启用 TUN。

**国内应用或网站变慢、无法加载：** 这常见于误用全局模式或规则没有命中。先改回规则模式，再阅读 [直连、规则与全局代理有什么区别](/posts/39-direct-rule-global-proxy-modes-guide)；不要把“所有流量都经代理”当成默认解决方案。

## 五、何时需要 TUN：只在系统代理验证成功之后

TUN 是更底层的转发方式，可覆盖不遵守 Windows 系统代理的应用。它会涉及虚拟网卡或服务权限，因此排错范围比系统代理更大。**系统代理尚未跑通时，不应把 TUN 当作第一步。**

1. 先关闭其他 VPN、虚拟网卡工具和代理客户端，确认上一节的系统代理仍能正常使用。
2. 在客户端设置中启用 TUN；首次启用可能要求管理员授权或安装组件。只接受来自已核验的官方客户端的正常授权请求。
3. 启用后先测试一个浏览器网页，再测试原先不走系统代理的应用。每次只测试一个变量。
4. 若发现所有软件都无法联网，立即关闭 TUN；确认系统网络恢复后再继续查日志。

**正常结果：** 浏览器仍可访问，原先不遵循系统代理的应用也能按规则连接，且没有持续断网或反复弹授权。

**TUN 后全部断网：** 不要重置 Windows 网络、不必关闭安全防护。先关闭 TUN，退出其他代理/VPN，再以管理员身份重新启动 Clash Verge Rev 后仅验证系统代理。若 TUN 仍失败，保留系统代理作为可用方案，并记录日志中的第一条错误；TUN 不是所有人都必须使用的功能。

## 六、Windows 休眠、切换 Wi-Fi 后不能访问

笔记本从睡眠唤醒、从家中 Wi-Fi 切到手机热点、或从有线网络切换到无线网络后，旧连接可能仍保留在客户端里。此时“节点列表存在”不等于当前网络已经重新建立连接。

按这个顺序处理：

1. 先确认 Windows 自己能打开普通网页；如果不能，先解决 Wi-Fi、热点或校园/公司网络认证。
2. 在客户端停止当前连接或关闭系统代理，等待网络恢复后再重新开启系统代理。
3. 只刷新一次订阅或重新选择当前节点；不要连续点刷新。
4. 若只有某些域名异常，查看 [网络测速、DNS 与连通性诊断指南](/posts/38-network-speed-dns-diagnostics-guide)，按“网络、节点、规则、DNS”的顺序确认。

**校园网或公共 Wi-Fi：** 这类网络可能要求先在浏览器完成认证。先关闭系统代理或 TUN，用 Safari 以外的 Windows 浏览器访问认证入口完成登录，再恢复客户端；不要把认证页不出现误判为订阅故障。

## 七、常见问题（FAQ）

### Clash Verge Rev 日志出现 `address already in use` 或“端口已被占用”怎么办？

这表示本机已有程序正在使用同一个监听端口，常见来源是另一款代理客户端、旧版本后台进程或本地开发工具。完全退出其他代理工具后重启 Clash Verge Rev；若仍存在，查看是哪一个程序占用该端口，再按客户端设置更换其控制端口。不要同时运行两个代理客户端来“互相测试”。

### 开启系统代理后网页全部显示无法连接，关闭后又正常，应该先查什么？

说明问题出现在客户端、节点或规则路径，而不是 Windows 的基础联网。先保持系统代理关闭，确认普通网络正常；随后更换一个节点并在规则模式下重新开启。若节点可选却所有目标都失败，再按 [网络测速、DNS 与连通性诊断指南](/posts/38-network-speed-dns-diagnostics-guide) 核对 DNS、规则和实际出口。

### TUN 开启时出现服务模式操作超时、驱动安装失败或反复要求授权怎么办？

先停止继续授权，关闭 TUN，并检查是否有旧 VPN、网络过滤软件或另一个代理客户端同时运行。确认当前客户端来自官方发布页后，以管理员身份重新启动一次，只重试一次。如果仍失败，使用已验证可用的系统代理即可；不要通过禁用 Windows Defender、防火墙或下载第三方驱动来强行解决。

### 节点延迟显示 Unknown 或测试失败，是否代表订阅一定不能用？

不一定。测试服务依赖当前网络、规则和节点响应，单次失败不能直接证明订阅无效。先确认订阅更新时间和节点列表正确，再用一个节点进行实际网页测试；如果多个节点都无法建立连接，才按订阅、网络、DNS 和规则顺序排查。

### 电脑从休眠唤醒后客户端还显示开启，但网页打不开怎么办？

先关闭系统代理，确认 Windows 已重新连上 Wi-Fi 或有线网络；再重新打开系统代理并重新选一次节点。若问题只在切换网络后出现，先查本地网络与 DNS，不需要立即反复导入订阅。
