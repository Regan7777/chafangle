第一次配置网络客户端时，最容易卡住的往往不是“按钮在哪”，而是把几个不同的东西当成同一个：服务商账户、订阅链接、节点、配置文件、客户端和规则模式，分别解决不同的问题。若它们没有分清，用户会在“导入成功但不能访问”“测速有结果但应用没变化”“开了代理国内软件变慢”之间反复试错。

这篇入门指南只建立共同语言和选择路径。你拿到客户端后，不需要同时修改 DNS、切换全局模式、开启 TUN 或寻找转换站；先确认自己处于哪一步，再进入对应的设备教程即可。

## 一、先用一句话认识六个对象

- **账户或服务后台**：你与服务商管理套餐、设备数量和订阅的地方。它不等于客户端，也不应该由陌生人代为登录。
- **订阅链接**：后台为当前账户生成的配置地址，客户端用它拉取节点与规则信息。它常常包含权限凭据，应像密码一样保存，不能贴到群聊、截图或不明网站。
- **配置文件**：客户端读取后的本地内容。有的客户端直接显示“订阅”，有的会显示“配置”或“Profile”；名称不同，作用相近。
- **节点**：可选择的连接出口。一个订阅通常有多个节点；节点有延迟不等于网页、视频或某个服务一定可用。
- **客户端**：安装在 Windows、Android 或 iPhone 上的软件，用来读取配置、选择节点和控制本机流量。客户端本身不附带账户或可用节点。
- **规则模式**：客户端判断一条网络请求是直连还是使用节点的方式。它不是“速度档位”，而是流量应该走哪条路径的选择器。

可以把顺序理解为：**在后台取得订阅链接 → 导入对应设备的客户端 → 更新后看到节点 → 选一个节点 → 先用规则模式测试 → 只在需要时调整高级选项。** 少一步或顺序倒置，都会造成看似复杂的故障。

客户端应按设备系统选择，不要把 Windows 的操作照搬到 iPhone，也不要试图把一套桌面配置文件直接丢给 Android。系统权限、导入入口和代理方式不同，正确路径如下：

## 三、拿到订阅链接后，第一件事不是粘贴

先在服务商后台核对三件事：当前账户是否有效、套餐是否允许新设备、页面是否明确提供给你所选客户端的订阅格式。随后复制完整链接，但不要打开到公开浏览器页面，更不要把链接交给不明“在线订阅转换”网站。

导入客户端后，执行一次更新。此时要观察的是**更新时间、配置名称和节点/策略组是否出现**，而不是先看延迟数字。若更新后什么都没有：

1. 回后台重新复制一次链接，检查是否粘进空格、换行或引号；
2. 确认没有在同一客户端中重复添加同一条订阅；
3. 若页面报出 HTTP 401、403、404 或 429，分别按授权失效/访问限制、路径更换、请求过频理解，先回后台处理，不要反复刷新；
4. 只有确认格式不兼容时，才阅读 [订阅格式与安全转换指南](/posts/37-subscription-format-conversion-guide)，先看兼容边界再决定是否转换。

**正常结果：** 客户端显示最新更新时间，能看到节点或策略组。这个阶段只证明“配置已导入”，尚未证明网络路径、节点或 DNS 全部正常。

## 四、首次连接只验证一件事：基础路径是否建立

第一次选节点时，选名称清楚的一个即可。保持客户端的规则模式或默认推荐模式，启用它针对当前系统的基础代理开关，然后用浏览器访问一个常用网页和一个需要验证的目标网页。回客户端观察连接记录是否增加。

不要一开始就追求最低延迟，也不要同时开启全局模式、TUN、增强 DNS 和多条规则。一次只改变一个变量，出了问题才能知道是节点、系统权限、规则还是网络本身。

**正常结果：** 普通网页可以加载；目标网页有一致的访问结果；客户端的连接或日志出现对应记录。若所有页面都无法打开，先关闭客户端的代理开关，确认设备的原始网络仍可用，再从“换一个节点”开始，而不是删除重装。

如果看到延迟、测速和实际体验不一致，要区分“建立连接的耗时”和“持续传输”。DNS、规则、当前网络和目标站点都能改变结果。请按 [网络测速、DNS 与连通性诊断指南](/posts/38-network-speed-dns-diagnostics-guide) 的顺序检查，不要仅凭一个 Ping 数字下结论。

## 五、规则、直连与全局：初学者先知道边界

初学者通常不需要自行编写规则。规则模式的目标是按已有规则决定流量走向；全局模式会让更多流量经当前节点；直连则不通过节点。它们是不同用途，不是“哪个更高级”。

首次使用建议保持规则模式。出现国内常用应用、银行、外卖或校园认证页面变慢、加载异常时，先检查是否误用了全局模式；不要直接判断为节点坏了。关于每种模式实际会影响什么，以及何时切换，另见 [直连、规则与全局代理有什么区别](/posts/39-direct-rule-global-proxy-modes-guide)。

TUN 也不是入门必选项。它适合部分不遵循系统代理的应用，但会涉及额外的系统权限或虚拟网卡。只在基础系统代理验证成功、且确有应用不走代理时再开启；对应操作应回到该设备的具体教程完成。

## 六、遇到问题时按层排查，不按情绪乱点

把问题归到一层，效率会高很多：

1. **账户/订阅层**：更新是否成功？配置里是否有节点？错误是否为 401、403、404、429？
2. **客户端层**：是否只运行了一个代理客户端？是否已允许必要的系统权限？
3. **节点层**：换一个节点后，结果是否变化？不要连续切换几十个。
4. **规则层**：当前是规则、直连还是全局？目标请求是否可能被错误分流？
5. **网络/DNS 层**：关闭代理后网络是否本来就可用？是否刚切换过 Wi-Fi、热点、校园网或公司网络？

按这个顺序能避免把“校园网还没认证”当成“订阅失效”，也能避免把“浏览器扩展接管了代理”当成“TUN 必须开启”。需要具体的网络认证、DNS 或测速排查时，转到 [网络测速、DNS 与连通性诊断指南](/posts/38-network-speed-dns-diagnostics-guide)。

## 七、常见问题（FAQ）

### 我只有一个订阅链接，为什么还要安装客户端？

订阅链接只是远端配置地址，不会自动改变设备的网络路径。客户端负责把它读成节点和规则，并在设备上启用代理或 VPN 权限。没有客户端，链接不会替你建立连接。

### 导入后看到了节点，是不是说明已经能用？

不一定。它只说明客户端下载到了配置。还要选一个节点、启用相应的代理方式并进行实际网页测试；若失败，再看是节点、权限、规则还是 DNS 问题。

### 我能把订阅链接发给朋友帮忙“测试一下”吗？

不建议。订阅链接可能包含账户授权信息，分享后会增加流量被占用、设备数超限或配置泄露的风险。需要协助时，提供错误代码、客户端版本和不含链接的截图即可。

### 为什么开了客户端，国内应用反而变慢或无法加载？

先看是否误用了全局模式。规则模式通常更适合日常使用，因为它让本地服务保持直连、再把需要的请求交给代理。不要在问题发生时立刻改 DNS、TUN 和订阅；先参照 [直连、规则与全局代理有什么区别](/posts/39-direct-rule-global-proxy-modes-guide) 确认当前模式。

### 为什么订阅更新成功，节点列表还是旧的？

先确认更新时间是否真的改变，再回后台确认节点是否发生过调整。有些客户端会保留本地缓存；只刷新一次并重新进入节点页即可。若格式或链接状态存疑，先看 [订阅格式与安全转换指南](/posts/37-subscription-format-conversion-guide)。
