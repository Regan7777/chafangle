sing-box 是可运行 JSON 配置的网络客户端/内核平台。它比“导入订阅后点开关”的客户端更重视配置结构、内核版本与日志含义。本文不要求新手手改 JSON：先完成可验证的导入与连接；只有错误明确指向配置字段时，才回到提供配置的一方处理，避免用不明“修复片段”越改越坏。

## 先用一句话认识 sing-box

可以把 sing-box 理解为“按配置执行网络规则的引擎”。它接收一份配置或订阅，再依照里面写好的规则决定：某个请求是直连、经过哪个节点，还是被拦截。手机或电脑上看到的开关、节点列表、策略组和日志，都是图形客户端替你操作这个引擎的界面。

它**不是**服务商、不是节点，也不是一条订阅链接。安装 sing-box 只得到客户端；订阅或配置决定可用的节点和规则；节点最终能否使用还取决于服务端与当前网络。把这三者区分开，排错时才不会把“订阅解析失败”“VPN 权限未授予”和“节点连接超时”误当成同一个问题。

如果你只需要日常使用，不必从零编写 JSON：选择可信来源提供的兼容订阅，按本文导入、验证和查看日志即可。只有想自定义规则、多个出站或 TUN 行为时，才需要进一步理解配置字段；这三项的具体设计、验证与回退方法见 [自定义规则、多出站与 TUN 进阶指南](/posts/41-sing-box-custom-rules-outbounds-tun-guide)。

**学习路径：** 本文是 sing-box 的基础篇，先完成导入、连接和日志判断；确认基础配置可用后，再进入 [自定义规则、多出站与 TUN 进阶指南](/posts/41-sing-box-custom-rules-outbounds-tun-guide)。两篇应配合阅读，不建议跳过基础验证直接修改 TUN 或复杂规则。

## 一、先选官方文档与稳定版本

安装包、版本变化与废弃字段以 [sing-box 官方发布页](https://github.com/SagerNet/sing-box/releases) 和 [官方文档](https://sing-box.sagernet.org/) 为准。稳定版本与预发布版的配置兼容性可能不同；遇到导入失败时，先记录客户端与内核版本，不要直接升级到测试版来“碰运气”。

开始前准备完整订阅链接或 JSON 配置、一个正常联网的 Wi-Fi/蜂窝网络，以及能够查看应用日志的位置。订阅链接含个人凭据，不应公开、转发或交给未知转换页。

## 二、导入与首次验证：一次只验证一个变量

1. 在客户端的配置/订阅页面添加链接或导入 JSON；保存时使用能识别来源的名称。
2. 更新一次，确认配置条目、更新时间与节点/出站组是否出现；初次成功前保留旧配置。
3. 选择默认出站或策略组，启动连接；首次出现 Android/iOS/桌面系统的 VPN 或网络权限提示时，确认发起者是当前客户端后再允许。
4. 在同一网络下测试一个普通国内网站和一个实际目标网站，并记录所选出站名称。

**正常结果：** 连接状态持续运行，日志中有新请求，目标请求显示实际出站或策略组。只显示“运行中”不足以证明规则生效。

## 三、规则、系统代理与 TUN：不要一次全打开

规则模式根据域名、IP、应用或规则集选择出站；适合日常使用。全局代理只用于短时间判断“目标是否被规则误分流”；直连用于确认本地网络是否可用。三个模式的完整差异与验证步骤见 [直连、规则与全局代理的区别](/posts/39-direct-rule-global-proxy-modes-guide)。

系统代理只影响遵循系统代理设置的应用；TUN/虚拟网卡会接管更广泛的系统流量，因此排错时不要同时开启系统代理、TUN、其他 VPN 和多个客户端。先用最小配置连接成功，再按需要单独开启 TUN；开启后所有网络都异常时，立即关闭 TUN，保留日志并检查权限、旧 VPN 和设备管理策略。

## 四、读日志：先判断错误发生在哪一层

不同图形客户端的界面文字可能不同，但日志通常包含更稳定的结构化线索。以下错误彼此不是同一类问题：

| 日志关键字或状态 | 表示什么 | 首先处理 |
| --- | --- | --- |
| `invalid character`、`unexpected end of JSON input` | 导入内容不是完整 JSON，或响应被截断/替换 | 核对链接和响应内容；校园网登录页常会返回 HTML |
| `unknown field`、`unknown outbound`、`deprecated` | 配置字段或出站类型与当前内核版本不兼容 | 记录内核版本，让配置提供方输出兼容版本；不要删除字段猜测修复 |
| `JSON schema` / `config check` 报错 | 配置结构不符合当前规范 | 定位日志给出的字段路径，只修改那一个来源明确的字段 |
| `permission denied`、`operation not permitted` | TUN、路由或系统权限不足 | 关闭冲突 VPN，检查系统授权和设备管理策略 |
| `lookup … no such host` | DNS 无法解析目标域名 | 换网络复测，再按 DNS 诊断流程检查 |
| `context deadline exceeded`、`i/o timeout` | 到订阅地址、节点或目标站的连接超时 | 固定网络与出站复测一次，比较蜂窝和 Wi-Fi |
| `TLS handshake timeout`、`x509` | TLS 握手、时间或证书校验失败 | 开启自动日期时间；不要关闭证书校验来掩盖问题 |
| `connection refused` | 对端端口拒绝连接或地址不提供服务 | 确认配置的地址/端口来自有效来源，联系服务商核对 |

发生校园网、酒店或公司网络问题时，先关闭客户端并在浏览器完成认证页面。普通网页正常、蜂窝网络正常而该 Wi-Fi 失败时，问题更可能在该网络限制。排查次序参见 [网络测速与 DNS 诊断指南](/posts/38-network-speed-dns-diagnostics-guide)。

## 五、常见问题（FAQ）

### 为什么导入后立即报 `unknown field`，而不是节点测速失败？

这是配置解析阶段的字段兼容问题，尚未开始连接节点。截图或复制完整字段路径、客户端版本与内核版本，请配置提供方生成兼容配置；不要从论坛复制删除字段的方案。

### 启动 TUN 后全部应用断网，应该继续调 DNS 吗？

先关闭 TUN 恢复网络，再检查 VPN 权限、旧 VPN、系统代理和设备管理限制。TUN 已接管流量时，DNS 并不是第一优先级；恢复最小配置后再逐项开启功能。

### `lookup … no such host` 与 `connection refused` 都是“节点不可用”吗？

不是。前者在域名解析层失败，后者表示已经到达地址但对端拒绝端口；两者需要的证据和处理不同。前者先做 DNS/网络对比，后者核对配置来源与服务状态。

### 规则模式失败、全局代理成功，下一步该改哪里？

固定同一网络、同一出站和同一目标，查看日志中规则命中与最终出站；这说明应排查规则或规则集，而不是长期改为全局代理。具体判断参阅 [直连、规则与全局代理的区别](/posts/39-direct-rule-global-proxy-modes-guide)。

### 如何给支持人员提供日志而不泄露订阅？

只提供错误发生时间、客户端/内核版本、错误行及已打码的域名或节点名称；不要发送完整订阅 URL、令牌、账号或整份配置文件。
